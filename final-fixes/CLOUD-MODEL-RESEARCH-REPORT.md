# Model versions have outrun the routing table

As of 16 October 2026, the safest things to write now are the format-level parts of the expert briefs: how to prompt, how to structure output, how to label frames, and how to build QA rubrics. The weakest parts are anything tied to a specific model id, version or limit. Four findings drive this. First, Anthropic's current line is Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5, all with 1M context and 128K output, and Haiku 4.5 is no longer the current Haiku ([Anthropic models](https://platform.claude.com/docs/en/about-claude/models/overview)). Second, Google has deprecated gemini-3.5-flash and routes it to gemini-3.6-flash, recommending 3.6 or 3.8 ([Google](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash)). Third, OpenAI's GPT-6 family (Astra, Sol, Luna) now has GPT-6.1 Sol as its latest member ([OpenAI](https://developers.openai.com/api/docs/guides/latest-model)). Fourth, the Sora API was scheduled to end on 24 September 2026, so Sora should be treated as unavailable. Video-model successors (Seedance 2.5, Kling 4.0, Wan 3.0, PixVerse V6, LTX-2.5, Hailuo 03) exist or are announced, but nearly all video-model evidence is second-hand: from fal.ai guides, aggregators and practitioner blogs, not from the model makers. The Grok evidence is entirely secondary. The report therefore separates what is verified from the vendor's own page, what is verified only through intermediaries, and what is a gap. It ends with a list of what to hard-code, re-check and make configurable.

## Frontier LLM and VLM routing: Claude is firm, Gemini and GPT are partial, Grok is unverified

**Claude is the best-documented family.** The current models table lists Fable 5.1 (`claude-fable-5-1`, $10/$50 per MTok), Opus 5.5 ($4/$20), Sonnet 5.5 ($2/$10) and Haiku 5.5 (from $0.10/$0.50), all 1M context and 128K max output, with image input ([Anthropic models](https://platform.claude.com/docs/en/about-claude/models/overview)). Prices are USD, so conversion to AUD is still needed. Release dates run from Fable 5 on 9 June to Haiku 5.5 on 7 October 2026, and Sonnet 4.5 retires on the API on 30 November 2026 ([release notes](https://platform.claude.com/docs/en/release-notes/overview)). Mythos 5.1 is the same model as Fable 5.1 but restricted to verified organisations, so it cannot be a default route ([Mythos 5.1](https://platform.claude.com/docs/en/models/mythos-5-1/overview)).

Several API behaviours change how briefs must be written. Prefill returns a 400 on 4.6-and-later models, and Haiku 5.5 additionally rejects `budget_tokens`, `temperature`, `top_p` and `top_k` ([best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices); [release notes](https://platform.claude.com/docs/en/release-notes/overview)). Sonnet 5 likewise rejects non-default sampling parameters. Determinism must therefore come from schemas, effort and validation, not temperature. Structured outputs (`output_config.format`, JSON schema) and strict tool use are available on all current models, but numeric bounds, string lengths and `minItems` above 1 are not enforced, so score ranges and timecodes need client-side validation ([structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)). A refusal arrives as HTTP 200 with `stop_reason: "refusal"`, and a request truncated by `max_tokens` can break the schema, so parsing must branch on `stop_reason`. Asking for a "reasoning" field in the output can itself be declined; the docs advise asking for a short explanation instead ([refusals](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)). Retrying a refused request on the same model usually earns another refusal, so a fallback model is needed, and the docs give no guidance for dark or violent fiction.

On prompting style, Anthropic's guidance is a one-sentence role in the system prompt, consistent XML tags, 3 to 5 diverse examples, long data first with the query last, and positive instructions over prohibitions ([best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)). Sonnet 5 follows instructions literally and does not generalise from one item to another, so scope must be stated ("every shot, not just the first") ([Sonnet 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5)). Opus 5.5 defaults to medium effort and the docs say to set effort explicitly and test several levels ([Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)). For vision, the docs say images work best before text, each introduced with a label such as "Image 1:"; extending that to "Frame 07, t=00:03.50" is a reasonable inference but not documented. Above 20 images per request a stricter 2000 px edge limit applies, and the high-resolution tier allows a 2576 px long edge ([vision](https://platform.claude.com/docs/en/build-with-claude/vision)). Bounding boxes should be requested as absolute `[x1,y1,x2,y2]` pixels in the resized image, never normalised 0-1000, and Anthropic calls them approximate, advising crop-and-reask for small targets ([coordinates guide](https://platform.claude.com/docs/en/build-with-claude/vision-coordinates)). Claude cannot ingest video (animated GIFs use the first frame only) and the docs say not to rely on it to detect synthetic images, so frame extraction and the QA framing are the platform's job.

**Gemini is the strongest option for native video QA, but the id list is stale.** The Gemini API takes video directly, sampling at 1 FPS by default with a configurable `fps`, about 66 or 258 tokens per frame by media resolution, and up to 10 videos per request; timestamps use `MM:SS` and the text prompt goes after the video ([video understanding](https://ai.google.dev/gemini-api/docs/video-understanding)). That 1 FPS default matters: a defect lasting under a second can be missed, so short clips need a higher `fps` and clipped re-inspection windows. Bounding boxes use `[ymin, xmin, ymax, xmax]` normalised to 0-1000, which is y-first and a common source of bugs ([image understanding](https://ai.google.dev/gemini-api/docs/image-understanding)). `gemini-3.8-flash` is stable with 1,048,576 input and 65,536 output tokens and thinking levels low, medium and high; "minimal" returns an error on it, which conflicts with the image-understanding page's advice to use minimal thinking for segmentation ([3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)). Pro and Flash-Lite ids on Google's own API, structured-output keyword limits and Google's prompting guide were not retrieved. OpenRouter lists `google/gemini-3.5-flash-lite` and `google/gemini-3.8-flash` ([OpenRouter](https://openrouter.ai/google/gemini-3.5-flash-lite)).

**GPT-6 is confirmed, but vision data is missing.** OpenAI names GPT-6 Sol and Luna with Astra as flagship, and a note dated 29 September 2026 points to GPT-6.1 Sol as latest; Sol is $2/$10 and Luna $0.10/$0.50 per million tokens ([OpenAI](https://openai.com/index/introducing-gpt-6-sol-and-luna/)). Ids per the OpenAI guide are `gpt-6-astra`, `gpt-6.1-sol`, `gpt-6-luna` and `gpt-6-sol`. Reasoning effort runs low through max; Astra and 6.1 Sol reject `none`, while GPT-6 Sol and Luna accept it; and `temperature`, `top_p` and `top_logprobs` must be removed when effort is not `none` ([OpenAI guide](https://developers.openai.com/api/docs/guides/latest-model)). Per-variant vision limits, video support, image token cost, coordinate conventions and strict-schema rules were not found, so GPT-6 should not be assigned localisation duties without testing. Through OpenRouter, `require_parameters: true` must accompany `response_format`, or a fallback provider may silently ignore the schema ([OpenRouter](https://openrouter.ai/docs/guides/features/structured-outputs)).

**Grok 4.7 exists per secondary sources only.** Third-party pages report `grok-4.7`, released 21 September 2026, with 500K context, $2/$6 per million tokens, configurable reasoning that cannot be disabled, and a May 2026 knowledge cutoff ([vpsranking](https://vpsranking.com/news/ai/ai-2026-09-21-xai-grok-47/); [Promptfoo](https://promptfoo.dev/docs/providers/xai)). Promptfoo also says 4.7 and 4.6 accept low to xhigh effort, while 4.3 (1M context) still accepts `none`. OpenRouter lists `x-ai/grok-4.7` ([OpenRouter](https://openrouter.ai/compare/anthropic/claude-sonnet-5.5/x-ai/grok-4.7)). Every attempt to read docs.x.ai, the grok-prompts repository and the current acceptable use policy was blocked, so no official xAI prompting guidance exists in the evidence. The only policy text found is a June 2026 version marked outdated, with no fiction carve-out ([xAI AUP](https://x.ai/legal/acceptable-use-policy/previous-2026-06-26)). One cautionary data point: xAI attributed a July 2025 incident to a prompt line telling Grok it was "not afraid to offend", so edgy-tone role lines should be replaced by explicit genre and scope boundaries ([Simon Willison](https://simonwillison.net/tags/xai/)).

## Video models: most successors exist, but the evidence sits behind intermediaries

**Version status.** Seedance 2.5 was reportedly released on 31 July 2026 with 30 s clips and up to 50 multimodal inputs ([Miracamp](https://www.miracamp.com/learn/content-creation/seedance-2-5-bytedance)), and fal lists `bytedance/seedance-2.5/reference-to-video` with a `task` field (reference, editing, extension), a `draft` mode, up to 30 images and 50 files ([fal](https://fal.ai/models/bytedance/seedance-2.5/reference-to-video/api)). Kling 4.0 rests on one third-party page reporting a 27 September announcement, 3 to 30 s clips, up to 10 keyframes and 4K, with launch "in October" ([Morphic](https://morphic.com/resources/models/kling-4)); whether it is live is unverified. Kling 3.0 is confirmed on fal ([fal](https://blog.fal.ai/kling-3-0-prompting-guide/)). Veo 3.1 (with Fast and Lite) is current on Google's API, and Gemini Omni Flash was announced on 19 May 2026 as a coexisting model ([Google](https://ai.google.dev/gemini-api/docs/veo?hl=fr); [Google blog](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-omni-experts-roundtable/)). Sora's app closed on 26 April 2026 and its API was due to end on 24 September 2026, per second-hand summaries of the OpenAI help article ([invideo](https://invideo.io/blog/sora-ai-video-generator/)); fal still documents Sora 2 endpoints, but they should be flagged unavailable. On fal, the newer ids found were Wan 3.0 (`alibaba/wan-3.0/...`), PixVerse V6, LTX-2.5 Pro and Fast, HappyHorse 1.0 and 1.1, Hailuo 03 (`minimax/hailuo-03`), Vidu Q4, and Luma Ray3.14 ([fal list](https://fal.ai/learn/tools/ai-video-generators)). HappyHorse is an Alibaba model, and "Omni" most plausibly means Gemini Omni Flash ([fal HappyHorse](https://fal.ai/happyhorse)). Grok Imagine is reported at 1 to 15 s, 480p or 720p, with native audio, on aggregators only ([fal](https://fal.ai/learn/tools/how-to-use-grok-imagine)).

**Prompt patterns converge, so a shared shot spec is viable.** Sources agree on subject-and-action first, one camera move per shot, verbs over mood adjectives, explicit audio lines, and "describe only what changes" for image-to-video. Seedance prompts are short briefs of about 60 to 100 words with role-labelled `@Image1` references ([fal Seedance](https://fal.ai/learn/tools/seedance-2-0-prompting-guide); [heyuan110](https://www.heyuan110.com/posts/ai/2026-07-11-seedance-2-prompt-guide/), practitioner). Kling 3.0 uses scene-direction prose, up to six labelled shots, and `[Character A: Role, voice descriptor]: "line"` dialogue with consistent labels ([fal Kling](https://blog.fal.ai/kling-3-0-prompting-guide/)). Veo takes quoted dialogue plus explicit SFX and ambient lines ([Google](https://ai.google.dev/gemini-api/docs/veo?hl=fr)). LTX wants one chronological paragraph with sound and camera ranked highest ([fal LTX](https://fal.ai/learn/tools/how-to-use-ltx-2-5)). Wan 3.0 accepts block briefs or timecoded beats with `enable_thinking` ([fal Wan](https://fal.ai/learn/tools/how-to-use-wan-3)). Hailuo 03 accepts timed blocks like "[0 to 2 seconds]" and up to 7,000 characters ([fal Hailuo](https://fal.ai/learn/devs/minimax-hailuo-3-prompting-guide-44-video-examples-fal)). Vidu Q4 is reference-driven, with about three beats per clip ([Pollo](https://pollo.ai/hub/how-to-use-vidu-q4), third party). Luma advises positive-only prompts of about 100 words in the present tense, avoiding "begins to" ([Luma](https://lumalabs.ai/learning-center/articles/luma-video-models-field-guide)).

The sharpest divergences are negative prompts, dialogue grammar, durations and gateway parameters. Negative prompts are a documented field on fal's Veo 3.1 and Kling v3 and on PixVerse V5.5, absent on Seedance 2.0, harmful on Luma, and expressed as prose "no X" clauses on Wan, Hailuo and Vidu. Hard limits worth encoding include Veo's 4/6/8 s clips, 24 fps, 16:9 or 9:16, and the rule that 1080p, 4K, references and extensions require 8 s ([Google](https://ai.google.dev/gemini-api/docs/veo?hl=fr)); Seedance 2.0's 4 to 15 s ([DataCamp](https://www.datacamp.com/tutorial/seedance-2-0-api-guide)); and Kling v3 on fal at 3 to 15 s ([fal](https://fal.ai/docs/model-api-reference/video-generation-api/kling-video-v3-pro.md)). Gateways differ materially: Krea's Kling wrapper has no negative prompt or elements and only 16:9 and 9:16 ([Krea](https://www.krea.ai/blog/kling-3-0-api-access-guide-pricing-code-examples-for-multi-shot-ai-video)), and Runway Gen-4.5 differs between Runway's site and Runware ([Runway](https://help.runwayml.com/hc/en-us/articles/46974685288467); [Runware](https://runware.ai/docs/models/runway-gen-4-5/guides/directing-motion)). Conflicts were found and should be resolved toward the more specific source: Kling's multilingual dialogue claim versus fal's Chinese-and-English-only endpoint note, HappyHorse's duration range, Vidu's 12 versus 15 reference images, and Luma's self-contradicting duration table.

## Film craft and VLM video QA: use narrow, evidence-bound questions

**Vocabulary is verifiable for the basics.** StudioBinder supplies verified shot sizes (extreme wide through extreme close-up, cowboy, medium close-up), angles (eye level, low, high, Dutch, bird's-eye), movements (dolly, pan, tilt, tracking, crane, Steadicam, dolly zoom), focus techniques (rack focus, shallow and deep focus, split diopter) and lighting terms (key, fill, rim, Rembrandt, motivated, practical) ([shots](https://www.studiobinder.com/blog/ultimate-guide-to-camera-shots/); [lighting](https://www.studiobinder.com/blog/film-lighting-terms/)). The 180-degree rule is verified ([StudioBinder](https://www.studiobinder.com/blog/what-is-the-180-degree-rule-film/)), as are the 30-degree rule, match on action and eyeline match ([Wikipedia](https://en.wikipedia.org/wiki/Continuity_editing)) and the J cut ([Wikipedia](https://en.wikipedia.org/wiki/J_cut)). Lens focal-length looks, grading terms, the L cut and the match cut come from background knowledge only, and the ASC glossary was never retrieved. No source shows that specific terms like "85mm" or "anamorphic" measurably change output; those are practitioner assertions.

**VLM judges are unreliable at exactly the defects a film platform cares about.** VBench-2.0 agrees with human preference from 81.70% (Composition) to 99.46% (Human Identity), but its authors say current large models are unreliable evaluators of human anatomy and motion rationality, so they add specialist detectors there ([VBench-2.0](https://arxiv.org/html/2503.21755v2)). Spotlight found the best zero-shot VLM scored 0.250 against 0.508 for humans, 78% of sampled Gemini 2.5 Pro outputs were wrong (29% hallucinated errors), only 48.7% of predicted timestamps were accurate, and multi-agent prompting with one query per error category gave the largest gain while chain-of-thought gave the least ([Spotlight](https://media.eventhosts.cc/Conferences/ECCV2026/pdfs/8243.pdf), a conference submission). Artifact-Bench reports Gemini 3.1 Pro best at 47.5 against 87.7 for human experts, with artefact identification below 10% for every model ([Artifact-Bench](https://arxiv.org/html/2605.18984v1)). Both used older or different models than the routing table, so they may understate current ones, but no newer evidence was found.

The resulting rubric design is well supported. Use one field per dimension, binary for hard defects and 1 to 5 for graded qualities, as VideoScore2 does with a rationale before the score; its exact 1-5 agreement was only 44.35%, versus 90.78% within one point, so decisions should use bands, not exact scores ([VideoScore2](https://www.alphaxiv.org/abs/2509.22799)). VideoPhy-2 scores semantic adherence and physical commonsense separately and checks named physical laws ([VideoPhy-2](https://videophy2.github.io/)). From the judge literature: reference-guided judging cut GPT-4 judge failure on maths from 70% to 15%, swapping order addresses position bias, and judges favour their own family ([Zheng et al.](https://arxiv.org/pdf/2306.05685)). Anthropic's evaluation guidance agrees: detailed rubrics, empirical outputs, thinking on, and a different grader than generator ([Anthropic](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests)). A sampling plan of first, last and one frame per second plus bursts at motion peaks, about 16 frames per pass with crops of faces, hands and text, is the report's own design, loosely grounded in a 5 fps default ([Artifact-Bench](https://arxiv.org/html/2605.18984v1)) and a forensic benchmark whose accuracy peaked at 16 frames ([arXiv](https://arxiv.org/html/2602.21779)). Lip-sync cannot be judged from silent frames; LSE-D and LSE-C are the standard automatic metrics ([Wav2Lip](https://arxiv.org/pdf/2008.10010)).

## What to write now, what to re-check, what to make configurable

| Decision | Items |
|---|---|
| Write confidently now | Claude role briefs (one-sentence role, XML, 3-5 examples, schema output, scoped instructions); labelled-frame prompt layout; pixel-coordinate bbox requests for Claude and the y-first 0-1000 convention for Gemini; the shared canonical shot spec (subject, action, one camera move with pace, light, audio, dialogue, references with roles); film vocabulary from the verified lists; QA rubric structure (narrow per-defect yes/no, evidence and timestamp required, bands not exact scores, un-cited defects treated as unconfirmed) |
| Re-check before relying | Every Grok fact (re-read docs.x.ai and the current AUP); Kling 4.0 and Seedance 2.5 availability and parameters on the actual gateway; GPT-6 vision, video and strict-schema rules; Gemini Pro and Flash-Lite ids; Veo negative-prompt support and Google's own prompt guide; PixVerse V6, Vidu Q4, HappyHorse and Hailuo 03 exact parameter names (several fal API pages were blocked); Luma Ray 3.2; whether the Sora API is truly dead; Claude content-refusal behaviour on dark film themes |
| Make configurable | Model ids, aliases and routing tiers; effort or thinking level per role; prices (and AUD conversion); gateway parameter maps (duration encoding, aspect-ratio sets, audio toggle, negative-prompt field, reference syntax); per-model caps (shot count, word budget, reference counts, durations); per-model dialogue and negative-prompt rendering rules; frame-sampling rate, frames per pass and crop rules; QA pass thresholds and band edges; fallback chains |

The strongest design lesson is a two-layer adapter. The prompt-style layer (how a model wants words ordered, whether it takes quoted dialogue, whether negatives are allowed) changes slowly and is worth writing now. The parameter layer (ids, durations, ratios, reference limits) changes monthly and differs between provider-direct and every gateway, so it should be data. Dropping Sora, adding version-keyed entries for Seedance 2.5 and Kling 4.0, and pinning Claude, Gemini and GPT ids as configuration rather than code addresses the routing-table drift directly.

## Conclusion

The notes show a split in how reliable the evidence is. Text and vision model facts for Claude come straight from the vendor and are firm; Gemini and OpenAI are partly firm; Grok and nearly every video model are known only through intermediaries. For a platform that has been burned by spec drift, this suggests treating the video adapters as hypotheses, marking each field with its source tier, and verifying against the live endpoint on first use.

The QA evidence points to a counter-intuitive priority: more reasoning effort on a VLM judge is unlikely to fix hallucinated defects, whereas splitting into narrow questions, requiring cited timestamps, and corroborating with deterministic checks (optical flow, OCR, face similarity) is the better spend. Pairing a cheap VLM triage pass with targeted crop-and-reask and a different-family judge is better supported than one expensive judge pass.
